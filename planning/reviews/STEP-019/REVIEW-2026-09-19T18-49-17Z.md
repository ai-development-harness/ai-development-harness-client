## Findings

### F-A18 — High — Отложенное создание unit не fenced относительно `TEARDOWN`

**Location:** `docs/adr/ADR-007-crash-consistent-containment-lifecycle.md:29,43-49,53-57,65-69`; `planning/tasks/STEP-019.md:62-64,86-88`; `planning/tasks/STEP-002.md:65,83,86-88`.

**Scenario:** `create` из `RESERVED` уже начат, но unit ещё не discoverable. Cancellation/restart записывает `TEARDOWN`, не находит unit/child, создаёт `noChildEverAttached` receipt и освобождает lease. Старый create затем завершается либо stale supervisor продолжает его, создавая unit с прежними `unitKey`/nonce.

**Impact:** idempotent create запрещает лишь второй create, но не первый late completion. Budget уже переиспользован при существующем orphan unit; следующий startup блокирует admission, а crash-consistent accounting нарушен на admission boundary.

**Fix direction:** определить `creationIntent` и generation-bound create/revoke boundary либо equivalent synchronous platform primitive. Terminal receipt должен доказывать, что pending create не может завершиться. В STEP-002 добавить deterministic `create pending → TEARDOWN/receipt/release → delayed create`, включая restart: delayed create не создаёт unit/member, не меняет terminal record и не позволяет reuse до valid reconciliation.

### F-A19 — High — Не определены single-writer ownership и takeover для overlapping supervisors

**Location:** `docs/adr/ADR-007-crash-consistent-containment-lifecycle.md:23,29,35-37,43,53-57`; `planning/tasks/STEP-019.md:62,87`; `planning/tasks/STEP-002.md:65,83`.

**Scenario:** Два supervisor запускаются одновременно либо новый supervisor начинает recovery до fenced termination прежнего owner. Оба могут enumerates lifecycle state и открыть admission; `ownerGeneration` хранится в payload, но нет owner claim, global epoch или CAS takeover.

**Impact:** возможны double admission сверх limit, teardown живого `ACTIVE`, concurrent release/delete и stale-owner mutation после takeover.

**Fix direction:** закрепить доказанный singleton invariant либо durable global supervisor epoch/lease. Capacity check + `RESERVED` должны быть одной linearizable transaction; admission открывается только в current recovery epoch, takeover — только после fence прежнего owner, а create/activate/teardown/release валидируют epoch. Handoff должен покрыть two-overlapping-supervisors и paused-old-owner-resume, исключая double release и teardown active request без valid takeover.

### F-A20 — Medium/High — Полное supersede ADR-006 теряет действующие security и compatibility guarantees

**Location:** `docs/adr/ADR-007-crash-consistent-containment-lifecycle.md:6,19,89-99`; `docs/adr/ADR-006-containment-boundary-repository-projection.md:15-21,39-47`; `planning/tasks/STEP-019.md:65,75,90-91`.

**Scenario:** После PASS ADR-006 предполагается сделать historical/superseded, а ADR-007 — current. ADR-007 определяет lifecycle, но не инкорпорирует bounded lexical-only parent validation, descriptor-first identity, trusted spawn profile, запрет network/child-process capability, обязательные resource limits, закрытие inherited FD/env/raw stderr, immutable caller settlement и success только после teardown.

**Impact:** implementer может считать ADR-006 полностью неактуальным и построить lifecycle-capable profile без сохранения прежней security/compatibility boundary.

**Fix direction:** либо оставить ADR-007 дополнительным lifecycle ADR, сохранив ADR-006 current для остальных clauses, либо явно перенести в ADR-007 все неизменяемые guarantees и их fail-closed postconditions. Current traceability и STEP-002 acceptance/tests обязаны однозначно сохранять эти guarantees.

### F-A21 — Medium/High — `attachIntent` не доказывает наличие child для terminal receipt

**Location:** `docs/adr/ADR-007-crash-consistent-containment-lifecycle.md:53,55,65`; `planning/tasks/STEP-002.md:87-88`.

**Scenario:** `attachIntent` durable зафиксирован до/в момент первого возможного spawn/attach, но crash или platform failure происходит до фактического создания child. Contract требует `directChildReaped` после любого recorded intent, хотя reaper-observable child может не существовать.

**Impact:** recovery не может получить ни корректный reap proof, ни `noChildEverAttached`; lease либо удерживается навсегда, либо освобождается по ложному proof.

**Fix direction:** durable разделить intent и доказанный spawn outcome/child identity, либо требовать primitive, при котором committed intent означает reaper-observable child. Иначе добавить отдельный строго доказуемый no-child proof для intent без child. Matrix должна включить `intent committed → spawn failed/no child` и проверить retained budget и exactly-once release.

### F-T11 — High — Executable plan STEP-002 противоречит oracle terminal child proof

**Location:** `planning/tasks/STEP-002.md:83` против `planning/tasks/STEP-002.md:65,69,87-88`; `docs/adr/ADR-007-crash-consistent-containment-lifecycle.md:53-55,65-67`.

**Scenario:** Pre-spawn recovery из `RESERVED`/`CREATED`/`BOUND` с доказуемым `attachIntent=absent` должен закончиться `noChildEverAttached`, но implementation plan разрешает release только после unconditional `direct-child reap`.

**Impact:** implementation и suite получают несовместимые oracle: корректный pre-spawn crash либо удерживает capacity навсегда, либо требует фиктивный reap.

**Fix direction:** синхронизировать executable plan с mutually exclusive proofs: `directChildReaped` допустим только при подходящем persisted child outcome, `noChildEverAttached` — только при доказуемом no-child path. Добавить отдельные exact-once regressions для обоих путей.
