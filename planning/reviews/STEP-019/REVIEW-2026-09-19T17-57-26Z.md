## Findings

### F-S12 — High — Receiver fence остаётся TOCTOU-проверкой

**Location:** `docs/adr/ADR-007-crash-consistent-containment-lifecycle.md:33,35,63-65,93`; `planning/tasks/STEP-019.md:62-64,87-88`; `planning/tasks/STEP-002.md:65,69,87`.

**Scenario:** Release handler читает committed `ACTIVE`, open channel и generation `G`, успешно проходит receiver-side check, затем приостанавливается до перехода `inert → running`. Supervisor durable фиксирует `TEARDOWN`, generation `G+1` и `revoking`, после чего начинает close/drain. Handler возобновляется с cached successful check и запускает untrusted I/O. Drain может дождаться handler, но не отменяет уже начавшийся blocking I/O.

**Impact:** Delayed release всё ещё может открыть I/O после durable fence; poison filesystem способен оставить worker в uninterruptible state и исчерпать admission budget.

**Fix direction:** `validate generation/token/channel + consume release + inert→running` и `TEARDOWN intent + generation revoke` должны разделять единую linearization boundary либо эквивалентный atomic platform primitive. Добавить deterministic regression `receiver check passed → pause → TEARDOWN intent/revoke → resume before running`, доказывающую, что после победившего teardown untrusted I/O не начинается.

### F-A17 — Medium/High — Terminal receipt не определяет proof для states без direct child

**Location:** `docs/adr/ADR-007-crash-consistent-containment-lifecycle.md:41-42,45,53,63`; `planning/tasks/STEP-002.md:69`.

**Scenario:** Crash происходит сразу после durable `RESERVED` до OS mutation либо после `CREATED` empty unit. Recovery-only edge ведёт в `TEARDOWN`, но release разрешён только по terminal receipt, который безусловно связывает empty proof и подтверждение reap direct child. В этих states child ещё нельзя было attach/spawn, поэтому literal reap proof получить невозможно.

**Impact:** Реализация либо навсегда удерживает capacity после безопасного pre-spawn crash, либо синтезирует proof вне принятого contract.

**Fix direction:** Terminal receipt должен содержать generation-bound mutually exclusive proof: `direct child reaped` либо `no child was ever spawned/attached`. Второй вариант требует durable spawn/attach intent, исключающего ambiguity. Crash tests после `RESERVED`/`CREATED` должны доказывать корректный cleanup и exactly-once release без фиктивного reap.
