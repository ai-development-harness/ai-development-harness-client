### F-001 — Medium — Удалена regression-проверка privilege boundary web domain

**Location:** `apps/local-service/src/repository-projection.spec.ts:1`; удалённый baseline `HEAD:apps/local-service/src/repository-projection.spec.ts:532`

**Scenario:** Given конфигурация ESLint является единственным executable enforcement для запрета `require('node:fs')`, `globalThis.process` и `window.process` в `apps/web`, When правило будет удалено, переопределено либо перестанет матчить один из обходных синтаксисов, Then текущие `yarn nx lint web` и web tests останутся зелёными, потому что они проверяют только фактический безопасный source и больше не выполняют negative probes.

**Impact:** regression может вернуть UI прямой filesystem/process access вопреки REQ-011 и публичной `ClientApi` boundary, а verification STEP-021 её не обнаружит. Удалённая suite не зависела от legacy repository success path, поэтому её удаление выходит за плановую замену несовместимых success-path assertions и ослабляет существующий security contract.

**Fix direction:** восстановить negative ESLint probes в отдельном owning test либо сохранить их в текущем spec; доказать запрет CommonJS `require`, `globalThis.process` и `window.process` тем же реальным workspace ESLint config.

### F-002 — Medium — Удалена negative type-проверка Git unavailable policy ADR-004

**Location:** `apps/local-service/src/repository-projection.spec.ts:4`; удалённый baseline `HEAD:apps/local-service/src/repository-projection.spec.ts:12`

**Scenario:** Given `GitProjection` остаётся публичной частью `ClientApi`, When будущая правка разрешит `branch`/`upstream`/divergence для ветви `available: false`, Then affected typecheck сможет пройти, потому что прежний `@ts-expect-error` proof удалён, а новый focused test проверяет только `ProjectionError.PLATFORM_UNSUPPORTED`.

**Impact:** verification больше не закрепляет, что unavailable Git projection не раскрывает selected-repository metadata. **Fix direction:** вернуть compile-time negative assertion для `GitProjection` в отдельный public-contract test либо в текущий spec, сохранив `@ts-expect-error` на metadata ветви `available: false`.
