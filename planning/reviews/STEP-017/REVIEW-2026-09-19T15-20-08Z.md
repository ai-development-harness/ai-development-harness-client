## Findings

- **F-001 — Medium — Потоковый iterator не ограничивает общее число directory entries.**
  - Location: `apps/local-service/src/repository-projection.ts:93-105`; `docs/adr/ADR-004-bezopasnaya-git-worktree-proektsiya.md:43-45`.
  - Scenario: `opendir()` действительно не материализует весь каталог, но limit увеличивается только для имён, совпавших с `STEP-*.md`. Untrusted `planning/tasks` может содержать произвольное число файлов с другими именами; loader последовательно обойдёт их все и не достигнет `maxStepCount`. Focused regression для превышения общего entry limit отсутствует.
  - Impact: attacker-controlled repository сохраняет неограниченную по числу entries filesystem/CPU работу на одном `loadRepository`, хотя Accepted ADR-004 явно требует bounded count/complexity и предыдущая remediation должна была обеспечить раннюю остановку directory enumeration. Для многочисленных artifacts failure остаётся небounded до фильтрации.
  - Fix direction: считать каждую полученную directory entry и fail closed при небольшом фиксированном общем limit независимо от имени; отдельным лимитом при необходимости оставить число подходящих STEP artifacts. Добавить regression, где лимит превышен только non-STEP entries и iterator прекращает чтение с typed error.

## Remediation status предыдущих findings

- Один root descriptor теперь удерживается на весь `loadRepository`; все чтения artifacts и enumeration выполняются относительно него.
- Каждый artifact segment ниже root открывается descriptor-relative через `/proc/self/fd` с `O_NOFOLLOW`; final files используют `O_NONBLOCK`, а type/size/bytes связаны с тем же descriptor.
- File read ограничен заранее выделенным буфером не больше `maxArtifactBytes`; рост файла после `fstat` больше не расширяет чтение.
- STEP artifacts загружаются последовательно, без `Promise.all` по attacker-controlled списку.
- Production source не запускает Git subprocess и всегда возвращает typed `SECURITY_POLICY` unavailable без branch/upstream/divergence.
- ADR-004, STEP-002, STEP-013, REQ-001/REQ-008/REQ-011 и PLAN/STATUS согласованы по dependency, capability owner и traceability.

## Verdict rationale

Root-descriptor, no-follow/non-blocking traversal, bounded file read, sequential artifact loading, Git subprocess boundary и документальная correction реализованы. Однако заявленный streamed entry limit остаётся обходным: фильтрация происходит до счётчика, поэтому untrusted каталог может заставить loader перечислить неограниченное число entries. Это прямое нарушение обязательного resource-limit contract Accepted ADR-004, поэтому verdict — `FAIL`.
