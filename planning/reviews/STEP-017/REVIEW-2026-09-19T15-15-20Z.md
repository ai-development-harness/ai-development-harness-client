## Findings

### F-001 — High — selected root не закреплён одним descriptor/identity на весь projection

- **Location:** `apps/local-service/src/repository-projection.ts:27-39,50-63,83-94,152-164`; `docs/adr/ADR-004-bezopasnaya-git-worktree-proektsiya.md:19-23,43-45`.
- **Preconditions:** selected root или один из контролируемых родительских каталогов может быть заменён во время `loadRepository`.
- **Defensive scenario:** `realpath()` и `lstat()` проверяют path до чтения, но каждый artifact повторно открывает `root` по имени. Между чтением manifest, scaffold, Execution Status и STEP каталог по тому же canonical path может находиться другой directory identity. `O_NOFOLLOW` защищает компоненты ниже вновь открытого root descriptor, но не связывает все операции с одним изначально проверенным root inode.
- **Impact:** service может собрать одну успешную projection из разных filesystem identities и обратиться к данным вне первоначально выбранного directory identity. Это нарушает fail-closed root boundary и позволяет подменить canonical repository facts в пределах одного load.
- **Mitigation:** один раз открыть canonical root directory, сохранить и проверить его `dev`/`ino`, выполнять все artifact traversal и directory enumeration относительно этого descriptor; при несовпадении identity или недоступности безопасной primitive возвращать typed operational/root-identity failure.
- **Regression test:** детерминированно подменить root identity между двумя чтениями через test seam и подтвердить fail-closed typed result без смешанной projection.

### F-002 — Medium — STEP enumeration остаётся path-based и не имеет bounded entry/concurrency limit

- **Location:** `apps/local-service/src/repository-projection.ts:83-94`; `docs/adr/ADR-004-bezopasnaya-git-worktree-proektsiya.md:43-45`.
- **Preconditions:** untrusted selected root содержит очень большой `planning/tasks` либо промежуточный directory component меняется во время enumeration.
- **Defensive scenario:** `lstat(directory)` и `readdir(directory)` выполняются по path вне descriptor-relative helper. `readdir` сначала материализует все entries, затем фильтрует STEP names, поэтому `maxStepCount` не ограничивает фактический объём enumeration. После этого до 500 artifacts читаются одновременно через `Promise.all`.
- **Impact:** специально подготовленный repository способен вызвать неограниченную по числу directory entries работу и крупный одновременный I/O/memory burst; path-based enumeration также не наследует no-follow гарантию текущего artifact reader. Это противоречит обязательным limits size/count/complexity/concurrency ADR-004.
- **Mitigation:** перечислять `planning/tasks` относительно закреплённого root descriptor, отклонять symlink/replacement, потоково ограничить общее число directory entries и читать STEP artifacts с малым фиксированным concurrency limit.
- **Regression test:** проверить bounded отказ для каталога с превышением общего entry limit и доказать ограничение числа одновременных artifact reads.

## Confirmed controls

- Каждый компонент artifact path ниже открытого directory descriptor проходит `O_NOFOLLOW`; final file открывается с `O_NONBLOCK`, а type/size и bytes связаны одним descriptor.
- Focused tests закрывают leaf/intermediate symlink, FIFO, oversized artifact, repository-owned validator, Git fsmonitor/filter sentinels и typed `SECURITY_POLICY`.
- Production source `apps/local-service/src` не импортирует `node:child_process` и не запускает Git; `loadGit()` всегда возвращает `{ available: false, worktree: 'unavailable', unavailableReason: 'SECURITY_POLICY' }`.
- Public `GitProjection.unavailableReason` включает `SECURITY_POLICY`; ADR-004 и STEP-013 запрещают Git capability без отдельного decision и security review.

## Verdict rationale

Remediation закрыла intermediate symlink и blocking FIFO ниже root descriptor, а Git boundary и typed policy result соответствуют ADR-004. Однако сам root descriptor/identity не удерживается на весь load, а STEP directory enumeration остаётся path-based и ресурсно неограниченной до фильтрации. Эти сценарии входят в заявленный untrusted filesystem threat model и не позволяют считать data-only boundary fail closed, поэтому verdict — `FAIL`.
