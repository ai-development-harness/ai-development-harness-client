## Findings

- **F-001 — High — Atomic no-follow remediation всё ещё допускает filesystem escape и blocking FIFO.**
  - Location: `apps/local-service/src/repository-projection.ts:27-42`; `apps/local-service/src/repository-projection.spec.ts:77-90`; `docs/adr/ADR-004-bezopasnaya-git-worktree-proektsiya.md:43-45`.
  - Scenario: `open(target, O_RDONLY | O_NOFOLLOW)` запрещает symlink только в последнем компоненте path. Untrusted root может заменить `.project`, `docs` или другой промежуточный каталог symlink на каталог вне root, после чего regular artifact будет открыт за пределами repository. Отдельно final FIFO открывается с blocking `O_RDONLY`: процесс зависает внутри `open` до получения descriptor, поэтому последующий `handle.stat()` не может fail closed. Имеющийся regression проверяет только заранее установленный final symlink; swap/intermediate-symlink/FIFO path не покрыты.
  - Impact: текущая data-only projection может читать файл вне selected root и без верхнего timeout удерживать local service на FIFO. Это нарушает Accepted ADR-004, который включает symbolic links, FIFO и hangs в threat model и требует atomic no-follow/type/size boundary.
  - Fix direction: разрешать каждый компонент пути относительно уже открытого root/directory descriptor без следования symlink либо применять эквивалентную platform boundary; открывать потенциальный artifact non-blocking до `fstat` и отклонять не-regular file на том же descriptor. Добавить deterministic regressions для intermediate-directory symlink и FIFO/замены до чтения, подтверждающие bounded fail-closed result.

- **F-002 — Medium — Roadmap projection не отражает исправленную dependency STEP-013 → STEP-017.**
  - Location: `planning/tasks/STEP-013.md:7`; `planning/PLAN.md:19`; `docs/requirements/SPEC.md:193-196`.
  - Scenario: task STEP-013 теперь корректно зависит от STEP-017, ссылается на ADR-004 и владеет REQ-008 capability boundary, однако строка STEP-013 в `planning/PLAN.md` по-прежнему содержит только `STEP-005, STEP-007`.
  - Impact: canonical task и roadmap projection расходятся; пользователь или automation, читающие PLAN, могут считать STEP-013 исполнимым без принятой security boundary.
  - Fix direction: синхронизировать dependency STEP-013 в `planning/PLAN.md` с canonical task и повторно проверить projections/traceability.
