## Findings

### F-001 — Medium — Лимит STEP artifacts не ограничивает общее число directory entries

- **Location:** `apps/local-service/src/repository-projection.ts:93-105`; `docs/adr/ADR-004-bezopasnaya-git-worktree-proektsiya.md:45`.
- **Preconditions:** выбранный untrusted root содержит очень большой `planning/tasks` с преимущественно не совпадающими с `STEP-\d+.md` именами.
- **Defensive scenario:** iterator проходит каталог до конца, а `maxStepCount` увеличивается только для совпавших STEP-файлов. Поэтому формальный предел 500 не ограничивает фактическое число обработанных entries и объём filesystem work.
- **Impact:** repository projection может надолго занять local-service CPU/I/O и задержать обслуживание UI. Это нарушает обязательный bounded entry traversal и fail-closed resource policy ADR-004.
- **Mitigation:** считать все полученные directory entries и прерывать enumeration при небольшом фиксированном общем лимите; отдельно сохранить лимит числа допустимых STEP artifacts.
- **Regression test:** создать каталог, где общий entry limit превышен не-STEP именами, и подтвердить ранний typed отказ без обхода оставшейся части каталога.

## Confirmed controls

- Один root descriptor удерживается на весь `loadRepository`; artifact traversal выполняется относительно него с `O_NOFOLLOW` для каждого сегмента.
- Final artifacts открываются с `O_NONBLOCK`, type/size проверяются на том же descriptor; чтение ограничено размером, полученным из bounded `fstat`.
- STEP artifacts читаются последовательно, поэтому прежний неограниченный `Promise.all` устранён.
- Production source `apps/local-service/src` не импортирует `child_process` и не запускает Git; `loadGit()` всегда возвращает `{ available: false, worktree: 'unavailable', unavailableReason: 'SECURITY_POLICY' }`.
- Focused tests подтверждают bounded отказ для FIFO, leaf/intermediate symlink и oversized artifact, а также отсутствие запуска Git fsmonitor/filter helpers.
