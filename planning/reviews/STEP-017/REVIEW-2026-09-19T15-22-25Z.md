## Defensive scenarios

- **Directory-entry exhaustion.** Preconditions: selected root содержит более 1000 преимущественно non-STEP entries. Attack scenario: repository пытается обойти `maxStepCount`, используя имена, не совпадающие с `STEP-*.md`. Implementation увеличивает `entryCount` до фильтрации имени и немедленно возвращает typed `INVALID_REPOSITORY` при превышении общего limit, поэтому обход из предыдущего finding закрыт.
- **Path substitution и special files.** Preconditions: repository заменяет intermediate artifact segment на symlink либо final artifact на symlink/FIFO. Attack scenario: попытка чтения target вне root или блокировки local service. Один root descriptor удерживается на весь load; каждый последующий segment открывается descriptor-relative с `O_NOFOLLOW`, final file также с `O_NONBLOCK`, а type/size/bytes проверяются на том же descriptor. Boundary fail closed.
- **Repository-controlled Git execution.** Preconditions: root содержит filters, fsmonitor, hooks или malicious Git config. Attack scenario: helper запускается с правами local service. Production path не импортирует process execution API и всегда возвращает `{ available: false, worktree: 'unavailable', unavailableReason: 'SECURITY_POLICY' }` без Git discovery.
