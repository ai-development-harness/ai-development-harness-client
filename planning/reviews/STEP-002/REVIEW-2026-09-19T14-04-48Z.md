## Findings

- **F-001 — High — открытие выбранного repository исполняет недоверенный Python-код.**
  - Location: `apps/local-service/src/repository-projection.ts:153-158,168-173`.
  - Scenario: `loadRepository(projectRoot)` запускает `python3 tools/harness/validate.py` с `cwd=projectRoot` до установления доверия. Crafted directory может содержать payload по этому пути; сам validator также импортирует sibling modules, поэтому проверка одного файла недостаточна.
  - Impact: code execution с правами local-service при обычном открытии directory; fixed argv не защищает от доверия к выбранному executable.
  - Fix direction: read/open path не должен исполнять файлы из `projectRoot`. Нужен trusted bundled verifier с `projectRoot` как data либо data-only inspection; repository-owned tooling допустим только после отдельной trust/capability границы и проверки всей executable closure.

- **F-002 — High — Git-unavailable не может стать projection fact, а BLOCKED маскируется как invalid repository.**
  - Location: `apps/local-service/src/repository-projection.ts:153-174`.
  - Scenario: canonical validator запускается до `loadGit`; при unavailable Git index он завершается `BLOCKED`/exit 2, а service сворачивает любой non-zero/spawn error в `INVALID_REPOSITORY`.
  - Impact: предусмотренное планом состояние `{ git: { available: false } }` недостижимо; UI не различает damaged repository, tooling failure и Git absence.
  - Fix direction: разделить integrity failure, BLOCKED и IO/tooling errors; Git availability не должна быть precondition read projection. Добавить controlled no-Git regression.

- **F-003 — High — Git read path также может исполнять repository-controlled helper.**
  - Location: `apps/local-service/src/repository-projection.ts:115-121`.
  - Scenario: `git status` в выбранном repository может активировать configured `core.fsmonitor` helper.
  - Impact: даже после устранения F-001 open path сохранит code execution из недоверенного directory.
  - Fix direction: до trust boundary не запускать Git либо жёстко отключить repository-controlled execution/config helpers через trusted configuration; добавить sentinel regression.

- **F-004 — Medium — tests не доказывают required projection facts на isolated repository.**
  - Location: `apps/local-service/src/repository-projection.spec.ts:34-71`.
  - Scenario: единственный positive case использует current workspace, хотя plan требует temporary isolated fixtures. Нет successful pre-init fixture, controlled Git-unavailable case или integration cases missing/malformed/invalid Execution Status через `loadRepository`.
  - Impact: acceptance `initialized`/`pre-init`/`invalid`, Git и Execution Status projections не доказан и тест зависит от environment.
  - Fix direction: после устранения executable trust boundary добавить isolated data-only fixtures для всех projection states, включая malicious validator/fsmonitor sentinel.
