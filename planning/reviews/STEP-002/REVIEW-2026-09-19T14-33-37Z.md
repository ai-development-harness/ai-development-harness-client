## Findings

- **F-001 — High — data-only loader неверно классифицирует pre-INIT и ordinary directory.**
  - Location: `apps/local-service/src/repository-projection.ts:41-91,240-289`.
  - Scenario: canonical pre-INIT template ещё не содержит `STEP-NNN`, поэтому `steps.length === 0` возвращает `INVALID_REPOSITORY`; одновременно manifest и искусственный минимальный STEP признаются initialized без обязательного Harness scaffold.
  - Impact: acceptance различения `pre-init`/`initialized`/`invalid` не доказан; downstream UI получает ложный source fact.
  - Fix direction: определить минимальный data-only contract отдельно для pre-init и initialized, не требовать STEP до INIT и покрыть fixtures, соответствующие template.

- **F-002 — High — STEP изменяет Harness-owned protocol/tooling.**
  - Location: `tools/harness/validate.py:40-55,313-324,696-707`, `docs/harness/CI.md:37-43`.
  - Evidence: `.project/harness-update.toml` относит `tools/harness/**` и `docs/harness/**` к `harness_owned`, а task заявляет отсутствие изменений Harness artifacts.
  - Impact: architecture drift и blocker будущего `HARNESS UPDATE`; local service больше не использует описанную capability.
  - Fix direction: убрать эти изменения из STEP-002 либо поставлять их отдельным canonical Harness release/update flow.

- **F-003 — High — Git worktree command исполняет repository-controlled filters.**
  - Location: `apps/local-service/src/repository-projection.ts:23-39,179-200`.
  - Scenario: `.git/config` задаёт `filter.<name>.clean` или `filter.<name>.process`, а `.gitattributes` применяет filter к изменённому файлу; `git status --porcelain` запускает helper. Security reviewer воспроизвёл создание sentinel при тех же аргументах и environment.
  - Impact: crafted repository выполняет произвольный код с правами local-service при открытии directory.
  - Fix direction: не выполнять worktree Git-команды над untrusted root до отдельной trust/capability boundary либо изолировать Git в OS sandbox; отключение отдельных config keys недостаточно.

- **F-004 — Medium — operational filesystem failures маскируются как invalid repository.**
  - Location: `apps/local-service/src/repository-projection.ts:94-121,240-296`; contract: `packages/client-api/index.d.ts:3-5`.
  - Scenario: `EACCES`, `ENOTDIR`, `EMFILE` и другие read failures, включая Execution Status, сворачиваются в `INVALID_REPOSITORY`/`invalid`.
  - Impact: валидный repository неотличим от неисправности local service или filesystem, хотя contract предусматривает `IO_ERROR`.
  - Fix direction: отделить parse/shape invalid от OS I/O errors и покрыть controlled `IO_ERROR` regression.

- **F-005 — Medium — Git projection не закреплена за selected root.**
  - Location: `apps/local-service/src/repository-projection.ts:179-235`.
  - Scenario: Git из вложенного directory без собственного checkout находит ancestor repository; `--show-toplevel` не сверяется с canonical selected root.
  - Impact: UI показывает branch/worktree/upstream другого repository.
  - Fix direction: определить root identity policy, canonicalize и сравнить Git toplevel с selected root до projection; добавить nested/external-gitdir fixtures.

- **F-006 — Medium — filesystem и subprocess operations не ограничены.**
  - Location: `apps/local-service/src/repository-projection.ts:73-101,179-223,240-264`.
  - Scenario: FIFO, symlink на device, oversized artifact или зависший Git блокируют `readFile`/subprocess; все STEP читаются без size/count/concurrency limits.
  - Impact: crafted directory создаёт local denial of service.
  - Fix direction: regular-file/containment/size/count checks, bounded concurrency и timeout с termination для subprocess; добавить blocking-artifact regression.

- **F-007 — High — обязательная Git projection с upstream/divergence не доказана.**
  - Location: `apps/local-service/src/repository-projection.ts:206-226`; tests: `apps/local-service/src/repository-projection.spec.ts:97-110`.
  - Evidence: test покрывает только dirty repository без upstream; отсутствуют clean fixture, `upstream`, `ahead` и `behind`.
  - Impact: обязательная часть implementation plan остаётся недоказанной.
  - Fix direction: добавить isolated committed fixture с upstream и контролируемым divergence.

- **F-008 — Medium — public API coverage Execution Status и invalid STEP artifacts неполна.**
  - Location: `apps/local-service/src/repository-projection.spec.ts:149-223`.
  - Evidence: нет successful `loadRepository` assertion для valid Execution Status (`availability`, `executionCount`, `raw`, `data`); отсутствуют public cases missing required STEP sections и malformed heading/status.
  - Impact: lossless valid projection и error path loader не доказаны.
  - Fix direction: добавить isolated public API fixtures для valid status и invalid STEP artifacts.

- **F-009 — Low — web boundary lint guard допускает CommonJS/global обход.**
  - Location: `eslint.config.mjs:8-20`.
  - Scenario: restricted imports не покрывают `require('node:fs')`, `globalThis.process` и `window.process`.
  - Impact: будущая Node-enabled renderer regression сможет обойти architectural guard; текущий web bundle privileged sinks не содержит.
  - Fix direction: запретить эти формы и добавить lint probes.
