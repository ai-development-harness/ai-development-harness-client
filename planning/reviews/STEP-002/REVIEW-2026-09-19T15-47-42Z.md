## Findings

- **F-001 — Medium — отказ procfs после начального probe ошибочно становится structural fact.**
  - Location: `apps/local-service/src/repository-projection.ts:58-65,69-92,175-188,222-228`.
  - Scenario: initial probe `/proc/self/fd` успешен, но subsequent `openContained`/`opendir` получает `ENOENT`; `errorResult` возвращает `INVALID_REPOSITORY`, а `readExecutionStatus` — `missing`.
  - Impact: operational failure platform capability выдаётся за repository state, что противоречит ADR-004.
  - Fix direction: централизованно классифицировать procfs failures на каждом descriptor traversal как `IO_ERROR` и добавить stateful regression для failure после probe и во время Execution Status.

- **F-002 — Medium — UI допускает stale ClientApi result при смене или снятии selected root.**
  - Location: `apps/web/src/app/app.tsx:11-18`; tests: `apps/web/src/app/app.spec.tsx:20-38`.
  - Scenario: A(slow) → B(fast) позволяет позднему result A перезаписать B; deselection root или замена client оставляет на экране прежний status.
  - Impact: UI показывает fact не текущего явно selected repository, нарушая REQ-001 и ADR-002.
  - Fix direction: очищать state при смене client/root, применить effect-scoped generation/cancel guard и добавить deferred-promise rerender regressions.

- **F-003 — Medium — filesystem projection не имеет deadline/cancellation для зависшего untrusted root.**
  - Location: `apps/local-service/src/repository-projection.ts:45-105,150-168,231-255`.
  - Scenario: crafted/unresponsive FUSE или NFS root удерживает `realpath`/`open`/`stat`/`read`/`opendir`; четыре calls навсегда занимают in-flight slots, а последующие получают `RESOURCE_LIMIT` до restart.
  - Impact: устойчивый DoS local-service и exhaustion libuv I/O pool; `O_NONBLOCK` защищает FIFO, но не blocking filesystem I/O.
  - Fix direction: выделить projection в cancellable isolated worker/process с hard deadline и teardown либо оформить отдельное architecture/corrective решение; добавить controllable hanging-I/O regression, подтверждающий освобождение slot после deadline.

- **F-004 — Medium — regression in-flight limit не проверяет реальную concurrency boundary.**
  - Location: `apps/local-service/src/repository-projection.spec.ts:225-233`.
  - Scenario: тест использует `maxInFlightLoads: 0` и один call; он не удерживает четыре normal calls, не доказывает rejection пятого и не проверяет reuse slot после completion.
  - Impact: declared resource protection остаётся неполностью доказанной.
  - Fix direction: добавить deterministic controllable async filesystem/projection seam и проверить overlap, rejection, release и subsequent successful load.
