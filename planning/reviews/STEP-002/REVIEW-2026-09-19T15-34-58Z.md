## Findings

- **F-001 — High — ordinary directory со сформированными placeholder artifacts принимается как initialized Harness repository.**
  - Location: `apps/local-service/src/repository-projection.ts:72-114,181-187`; tests: `apps/local-service/src/repository-projection.spec.ts:15-35,288-300`.
  - Scenario: fresh root с manifest `harness.release: fake`, пустыми `AGENTS.md`/`EXECUTION_PROTOCOL.md`/`SPEC.md`/`ADR TEMPLATE` и `STEP-1.md` с произвольным status возвращает `ok: true`, `validity: initialized`.
  - Impact: не доказано обязательное различение initialized/pre-INIT/invalid; UI получает ложный repository fact вопреки REQ-001 и acceptance STEP-002.
  - Fix direction: определить достаточный data-only structural contract для stable artifacts и STEP, проверить canonical ID/status/обязательные sections и добавить regression для fully-shaped placeholders без исполнения repository tooling.

- **F-002 — Medium — Git unavailable policy не закреплена в typed contract и regression tests.**
  - Location: `packages/client-api/index.d.ts:14-21`; tests: `apps/local-service/src/repository-projection.spec.ts:178-213,253-273`.
  - Scenario: `GitProjection` типобезопасно допускает `{ available: false, worktree: 'unavailable', branch, upstream, ahead, behind }`; partial `toMatchObject` assertions не поймают утечку этих фактов.
  - Impact: replaceable adapter может нарушить ADR-004, а UI сможет получить Git metadata при `SECURITY_POLICY`.
  - Fix direction: использовать discriminated union; в unavailable ветви сделать reason обязательным, а Git facts — `never`; добавить exact/negative и type-level assertions.

- **F-003 — Medium — отсутствие Linux procfs ошибочно становится INVALID_REPOSITORY.**
  - Location: `apps/local-service/src/repository-projection.ts:34-55,119-131,166-171`.
  - Scenario: недоступность `/proc/self/fd` даёт `ENOENT`, который `errorResult` сворачивает в `INVALID_REPOSITORY`; при чтении Execution Status аналогичный случай маскируется как `missing`.
  - Impact: на platform без procfs корректный repository получает ложный structural fact вместо typed operational `IO_ERROR`, противореча ADR-004.
  - Fix direction: отделить platform capability/operational I/O failure от absent artifact и покрыть injectable filesystem seam regression.

- **F-004 — Medium — aggregate resource boundary для untrusted repository отсутствует.**
  - Location: `apps/local-service/src/repository-projection.ts:11-13,59-66,94-116,174-187`; contract: `packages/client-api/index.d.ts:8-12`.
  - Scenario: 500 individually valid STEP artifacts почти по 1 MiB заставляют service прочитать и удержать около 500 MiB; concurrent `loadRepository` умножают расход.
  - Impact: crafted selected root может вызвать event-loop pressure или OOM local-service.
  - Fix direction: ограничить aggregate bytes/projection output, длину title/status и in-flight loads; добавить regression на превышение aggregate budget.

- **F-005 — Medium — web composition seam не доказывает и не реализует обращение UI к ClientApi.**
  - Location: `apps/web/src/app/app.tsx:9-16`; tests: `apps/web/src/app/app.spec.tsx:19-30`.
  - Scenario: `App` принимает, но намеренно игнорирует `ClientApi`; test проверяет только render и пройдёт при удалении всякого client call.
  - Impact: acceptance STEP-002 «UI обращается к typed ClientApi» и пункт 4 plan не доказаны.
  - Fix direction: добавить observable UI load seam с mocked ClientApi и assertion typed result/call либо явно скорректировать scope, если actual invocation отложен.
