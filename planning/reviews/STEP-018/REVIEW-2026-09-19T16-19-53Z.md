## Findings

### F-S03 — High — Обязательные OS guarantees всё ещё можно объявить residual risk

**Location:** `docs/adr/ADR-006-containment-boundary-repository-projection.md:15,20,39`; `planning/tasks/STEP-018.md:86-87`; `planning/tasks/STEP-002.md:82`

**Scenario:** Given будущая реализация containment unit с stable handle, kill-all и empty proof, when implementer не предоставляет network isolation, запрет/лимит дочерних процессов либо CPU/memory/PID limits, then ADR сначала требует эти ограничения через platform primitive, но сразу разрешает считать любое из них «сознательно не требуемым» для data-only load. ADR не перечисляет, какие гарантии обязательны именно для `loadRepository`, кто и когда может понизить их до residual risk и какая платформа/primitive является поддерживаемым success path.

**Impact:** реализация может вернуть успешную projection с неограниченными CPU, memory, PID/process или network capability и формально сослаться на residual risk. Это не доказывает resource budget и fail-closed platform limitation из acceptance STEP-018, оставляет original F-S03 частично открытым и позволяет `PLATFORM_UNSUPPORTED` либо небезопасный success выбирать без проверяемого критерия.

**Fix direction:** в superseding decision явно классифицировать каждую capability для единственного data-only load: mandatory guarantee либо конкретный accepted residual risk. Для mandatory набора определить проверяемые platform postconditions и хотя бы один поддерживаемый primitive/target либо честно зафиксировать отсутствие supported platform; STEP-002 tests должны отдельно доказывать каждый required limit и fail-closed при его отсутствии.

### F-S04 — High — Canonical path не атомарно связан с открытым root descriptor

**Location:** `docs/adr/ADR-006-containment-boundary-repository-projection.md:18`; `planning/tasks/STEP-018.md:85`; `planning/tasks/STEP-002.md:82`

**Scenario:** Given mutable/FUSE selected root, when child сначала выполняет `realpath`, а затем отдельно открывает root descriptor, then filesystem может заменить symlink/mount/path между операциями. IPC artifact получит canonical path от первого resolution и `dev`/`ino` другого объекта от descriptor; parent намеренно не делает recheck и не имеет правила, по которому отвергнет несовместимую пару.

**Impact:** projection может прочитать объект B, но идентифицировать его как root A. Это ломает source identity текущего load, допускает чтение за ожидаемой selected-root boundary при race и делает `canonical path + dev/ino` недостоверным security artifact.

**Fix direction:** определить единый descriptor-first/atomic root acquisition contract: filesystem reads выполняются только через итоговый descriptor, canonical identity выводится из того же открытого объекта либо его соответствие descriptor доказывается без повторного path race. Canonical path должен быть явно advisory, если такую связь платформа доказать не может; иначе возвращать typed operational/platform failure. Добавить deterministic race regression с заменой symlink/mount между resolution и open.

### F-005 — Medium — Typed result teardown противоречит немедленному settlement timeout/cancel

**Location:** `docs/adr/ADR-006-containment-boundary-repository-projection.md:18,21,43`; `planning/tasks/STEP-018.md:88`; `planning/tasks/STEP-002.md:64,82,85`

**Scenario:** Given deadline, after caller уже немедленно получил `IO_TIMEOUT`, when последующий kill-all, empty proof либо reap завершается ошибкой, then ADR одновременно требует продолжать teardown под lease и возвращать teardown failure как `IO_ERROR`. Один вызов `loadRepository` не может сначала settle `IO_TIMEOUT`, а затем заменить результат на `IO_ERROR`; отдельный supervisor-health/operational channel не определён.

**Impact:** будущая реализация и tests не имеют однозначного error precedence. Ошибка cleanup может быть потеряна, lease может навсегда остаться занятым без наблюдаемого состояния, либо реализация нарушит обещание немедленного settlement, ожидая teardown.

**Fix direction:** разделить immutable caller result и post-settlement supervisor outcome. Зафиксировать precedence для cancel/deadline versus concurrent spawn/protocol failures, durable/observable retained-lease state для failed teardown и условия, при которых `IO_ERROR` действительно является результатом текущего caller. Добавить отдельные tests для timeout → teardown failure и cancel → late teardown failure.
