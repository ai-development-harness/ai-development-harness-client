## Findings

### F-S09 — High — Не определена crash-consistent фиксация unit и admission lease

**Location:** `docs/adr/ADR-006-containment-boundary-repository-projection.md:18-20`; `planning/tasks/STEP-018.md:85-86`; `planning/tasks/STEP-002.md:82`

**Scenario:** Given будущий supported platform profile, when supervisor проходит `reserve lease → create private unit → получить stable handle → durable связать handle с record → attach worker`, then ADR одновременно требует получить lease до создания unit и durable записать identity unit «до admission». Identity ещё не существующего unit записать невозможно, а атомарная граница между OS unit и durable store не определена. Crash после создания unit, но до durable binding, оставляет live unit без recoverable record; restart считает capacity свободной и допускает новый spawn.

**Impact:** повторение crash-window позволяет обойти admission budget и накопить residual units/processes. Это вновь открывает resource-exhaustion класс F-S05, несмотря на корректную steady-state reconciliation уже известных records.

**Fix direction:** определить crash-consistent lifecycle, например `RESERVED → CREATED → BOUND → ACTIVE → TEARDOWN`: durable `RESERVED` существует до OS mutation; stable handle верифицируется и durable связывается до attach worker/untrusted I/O; incomplete, unknown и corrupt states при startup удерживают budget и fail-closed reconcile-ятся до нового admission. Добавить crash-injection regressions после каждого transition, отсутствие admission до empty proof + reap и exactly-once release lease.

### F-T07 — High — Future regression не доказывает fail-closed recovery неизвестного durable record

**Location:** `planning/tasks/STEP-002.md:68,85`; `planning/tasks/STEP-018.md:89`; `docs/adr/ADR-006-containment-boundary-repository-projection.md:19,21,39`

**Scenario:** Given после restart durable store содержит missing, unknown, unresolvable либо reconciliation-failed stable handle/record, when реализуется только generic test «residual unit → restart/reconciliation → no capacity reuse», then regression может покрыть лишь известный успешно найденный unit. Обязательная ADR-ветка unknown/unreconciled record остаётся непроверенной.

**Impact:** implementation может fail-open удалить либо не учитывать damaged record и освободить capacity без OS proof, снова обходя admission budget. Finding уже присутствовал в latest previous report и последним FIX не устранён.

**Fix direction:** добавить parameterized restart regressions для missing, unknown, unresolvable и reconciliation-failed record. Каждый сценарий должен доказать `RESOURCE_LIMIT`, отсутствие нового spawn/admission до empty proof + reap и освобождение ровно одного lease только после успешной reconciliation.

### F-T08 — Medium — Opaque observation после restart не имеет adversarial regression

**Location:** `planning/tasks/STEP-002.md:68,82,85`; `planning/tasks/STEP-018.md:88-89`; `docs/adr/ADR-006-containment-boundary-repository-projection.md:21,43`

**Scenario:** Given durable record и teardown diagnostics содержат poison values selected-root path, PID и raw stderr, when supervisor перезапускается и публикует восстановленный `TEARDOWN_FAILED`, then plan проверяет durable outcome и отдельно упоминает raw stderr, но не требует доказать отсутствие path/PID/raw diagnostics в observation/API/serialized read-only payload до и после restart.

**Impact:** recovery может сохранить accounting, но раскрыть attacker-controlled path или process diagnostics через read-only surface. Finding уже присутствовал в latest previous report и последним FIX не устранён.

**Fix direction:** добавить adversarial restart regression с poison path/PID/raw diagnostics. Публичная projection, IPC/loggable response и serialized read-only payload должны содержать только typed lifecycle, opaque unit identity и retained-lease flag.
