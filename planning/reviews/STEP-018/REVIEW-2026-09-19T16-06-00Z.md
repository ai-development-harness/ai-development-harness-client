## Findings

### F-S01 — High — `realpath` остаётся перед process isolation

**Location:** `docs/adr/ADR-005-otmenyaemaya-granitsa-repository-projection.md:11,21`; `planning/tasks/STEP-018.md:85-86`; `planning/tasks/STEP-002.md:81`

**Scenario:** Given selected root на зависшем FUSE/NFS, when parent должен передать child уже `canonicalized selected root`, then filesystem canonicalization через `realpath` может зависнуть в parent до запуска supervised child и вне его deadline/teardown.

**Impact:** заявленная boundary не обеспечивает bounded responsiveness local service для одной из операций, которую сам threat model считает неотменяемой. Acceptance criterion о hard deadline/cancellation для untrusted filesystem I/O не доказан.

**Fix direction:** не выполнять filesystem canonicalization/identity resolution в parent. Parent может делать только не обращающуюся к filesystem lexical validation/normalization входной строки; `realpath`, открытие root descriptor и проверка identity должны происходить внутри isolated child и возвращаться через versioned IPC. Поскольку ADR-005 уже имеет `Accepted`, исправление устойчивого решения должно соблюдать repository policy для Accepted ADR, включая новый superseding ADR, если требуется изменить decision.

### F-S02 — High — Не определена безопасная private process-group identity

**Location:** `docs/adr/ADR-005-otmenyaemaya-granitsa-repository-projection.md:23,27,65`

**Scenario:** Given child, который наследует process group parent либо завершает group leader до delayed escalation, when supervisor отправляет group-wide `SIGTERM`/`SIGKILL` только по PID/PGID, then сигнал может затронуть parent/соседние процессы или попасть в переиспользованную identity; один `exit` direct child также не доказывает исчезновение всей group.

**Impact:** teardown contract допускает collateral kill либо преждевременное освобождение lease при surviving descendants. Это нарушает и безопасность host, и no-capacity-reuse guarantee.

**Fix direction:** зафиксировать создание отдельной private session/process group до любого untrusted I/O, стабильную supervisor-owned identity/handle и проверяемое условие уничтожения всей containment unit. Для платформ без такой primitive — `PLATFORM_UNSUPPORTED`; escalation не должна сигналить потенциально переиспользованную PID/PGID.

### F-S03 — Medium — `isolated child` не имеет явного containment contract

**Location:** `docs/adr/ADR-005-otmenyaemaya-granitsa-repository-projection.md:21,25,57,65`

**Scenario:** Given spawn trusted entrypoint, when child наследует environment, file descriptors, cwd, loader hooks и network/process capabilities parent, then запрет shell и repository-controlled cwd сам по себе не доказывает заявленную isolation boundary и не ограничивает host resources процесса.

**Impact:** будущая реализация может считаться соответствующей ADR, оставаясь шире необходимой data-only capability; secrets/FDs и неограниченные CPU/memory/network остаются вне явно принятого threat model.

**Fix direction:** определить минимальный spawn profile: explicit safe cwd, allowlisted environment без loader hooks/secrets, закрытые/явно назначенные stdio/FDs, запрет dynamic loading из selected root, network/process capability policy и OS resource limits. Нереализуемые ограничения нужно явно обозначить как residual risk либо причину `PLATFORM_UNSUPPORTED`.
